# Easy-Web AI 能力技术设计文档

> 版本：v1.0 | 日期：2026-07-01 | 分支：`feat/ai-chat-memory`

## 1. 概述

在 Easy-Web 微内核之上增加 **AI 扩展层**，实现：

- OpenAI 兼容 LLM 接入
- Function Calling + Agent Loop
- 四层工程级记忆（SQLite）
- Skill 可插拔机制
- Chat 交互模式（本地辅助测试）
- CI 模式保持不变（`main.py` 确定性执行）

## 2. 架构

```
┌─────────────────────────────────────────────────────────┐
│  入口层                                                  │
│  main.py (CI/CD)          python -m ai.chat (Chat)      │
├─────────────────────────────────────────────────────────┤
│  AI 扩展层 (ai/)                                         │
│  chat.py │ agent_loop.py │ tool_executor.py             │
│  llm_client.py │ skills/registry.py │ notify.py         │
├─────────────────────────────────────────────────────────┤
│  记忆层 (ai/memory/)                                     │
│  MemoryManager — L1 Working / L2 Episodic               │
│                    L3 Semantic / L4 Procedural            │
│  store.py — SQLite @ data/ai/knowledge.db               │
├─────────────────────────────────────────────────────────┤
│  工具层 (ai/tools/)                                      │
│  L1 browser_* │ L2 run_case / validate │ L3 meta        │
├─────────────────────────────────────────────────────────┤
│  微内核 (不变)                                           │
│  Engine │ DataDriver │ ConfigLoader │ conftest          │
└─────────────────────────────────────────────────────────┘
```

## 4. 配置设计

**分层原则**：

- `config/settings.yaml`：非敏感默认值（model、temperature、agent、memory、skills）
- `.env`：敏感项与部署覆盖（API Key、Webhook、enabled/mock 开关）
- 加载顺序：YAML → `.env` 合并（见 `utils/env_loader.py`）

`config/settings.yaml` 片段：

```yaml
llm:
  enabled: false
  base_url: https://api.openai.com/v1
  model: gpt-4o-mini
  mock: false

agent:
  mode: hybrid             # assist | agent | hybrid
  max_steps: 20
  step_timeout: 30
```

`.env.example` 片段（复制为 `.env` 后填写）：

```ini
LLM_API_KEY=
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
LLM_ENABLED=false
LLM_MOCK=false
DINGTALK_WEBHOOK=
```

`settings.yaml` 其余段落（memory / skills / notify）结构不变；钉钉 Webhook 同样建议只写在 `.env`。

## 5. 四层记忆

| 层 | API | 读写时机 |
|----|-----|----------|
| L1 Working | `append_working` / `get_working_context` | 每轮 tool call |
| L2 Episodic | `save_episode` / `find_similar_episodes` | session 结束 / 成功修复 |
| L3 Semantic | `upsert_selector` / `rag_search` | 用例通过 / retrieve |
| L4 Procedural | SkillRegistry | 启动加载 / 晋升 |

**淘汰策略**：`mark_selector_stale`（CI 失败）、episode 超 90 天压缩摘要。

## 6. Tool 分层

### L1 浏览器（Agent 模式，需 engine）

- `browser_open`, `browser_click`, `browser_input`
- `browser_get_page_info`, `browser_screenshot`, `browser_get_text`

### L2 框架语义（推荐）

- `validate_test_case`, `load_test_cases`
- `run_test_case`, `save_test_case_staging`（写 staging，不直接污染 data/）

### L3 元操作

- `get_config`, `suggest_selector`, `memory_search`

## 7. Agent Loop

```
用户输入 → 加载 Skills + L3 retrieve → LLM(messages, tools)
  → tool_calls? → ToolExecutor → 结果写入 L1 → 循环
  → 无 tool_calls → 返回最终回复
终止: max_steps | task_complete | 用户 quit
```

## 8. 幻觉控制

1. `browser_get_page_info` 返回精简 DOM 元素列表（id/name/tag/text）
2. `suggest_selector` 只从 DOM 候选中推荐
3. `validate_test_case` 校验 REQUIRED_FIELDS
4. `run_test_case` 必须试跑后才允许 `save_test_case_staging`
5. 正式合并 `data/test_data.json` 需 CLI `--confirm-save`

## 9. Chat 使用

```bash
# 交互模式（mock，无需 API Key）
python -m ai.chat --mock "帮我生成一个登录测试用例"

# 指定 session 续聊
python -m ai.chat --session <id>

# 运行 AI 模块测试
pytest tests/ai/ -v
```

## 10. 与 CI 边界

- `main.py` / pytest **不默认启用** LLM
- 可选 hook：失败时若 `llm.enabled` 调用 `diagnose_failure` skill
- 所有 AI 产物先进 `data/ai/staging/`
