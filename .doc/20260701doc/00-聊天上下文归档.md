## 对话 1：AI 能力总体评估

### 用户问题
可否加点 AI 能力，比如配置 LLM 服务连接信息（兼容 OpenAI 接口标准），以及 SQLite RAG 是否值得做？

### 结论摘要
- **项目现状**：Easy-Web 是数据驱动 Web 自动化框架（Selenium/Playwright + pytest + Allure），无 AI 相关代码，但 `ConfigLoader` + YAML 扩展成本低。
- **LLM 接入**：强烈推荐。在 `settings.yaml` 增加 `llm` 配置块，`openai` SDK + `base_url` 兼容 DeepSeek/Ollama/vLLM 等。
- **高 ROI 场景（按优先级）**：
  1. 失败诊断（挂 `pytest_runtest_makereport`）
  2. 自然语言 → 标准 JSON 用例
  3. 选择器自愈（与 `robust_mode` 互补）
- **SQLite RAG**：Phase 2，知识库 > 100 条文档/用例/失败记录时再做；框架文档量小可直接进 prompt。
- **推荐路线**：P0 LLM Client → P1 失败诊断 → P2 用例生成 → P3 选择器自愈 → P4 RAG（按需）

## 对话 2：Function Calling、Loop、Skill

### 用户问题
Function calling 机制和 loop 机制呢？比如支持 skill 加强。

### 结论摘要
- **Function Calling**：把 `Engine`/`DataDriver`/`conftest` 封装为 Tool，分三层：
  - L1 浏览器原子操作（open/click/input/screenshot）
  - L2 框架语义操作（run_case_by_json、validate_test_case）— **优先使用**
  - L3 元操作（get_config、list_test_cases、get_last_failure）
- **Agent Loop**：ReAct 循环，终止条件 `max_steps`、超时、人工确认写操作。
- **三种模式**：Assist（0~1 轮）、Agent（多轮）、Hybrid（推荐：生成→试跑→失败 heal→再跑）。
- **Skill 机制**：`skills/*/SKILL.md` + 可选 `tools.py`；SkillRegistry 合并 tools + system prompt；按 trigger 激活。
- **与 RAG 关系**：Skill=怎么做，Function Calling=做什么，RAG=查什么；RAG 可作为 Skill 内部能力。

## 对话 3：Chat 模式与知识飞轮

### 用户问题
是否可以做 chat 模式，测试通过的代码自动缓存、落 RAG、抽离成 skill，脚手架越用越聪明？

### 结论摘要
- **双模式**：CI/CD（`main.py` 确定性）+ Chat（`python -m ai.chat` 交互式）。
- **知识飞轮**：Chat 探索 → 通过 → L1 结构化资产 → L2 RAG → 统计 pattern → L3 Skill 晋升 → 合并 data/ → CI 验证 → 失败降权。
- **缓存分层**：
  - 自动：session、tool_calls、screenshot 路径
  - 需确认：写入 `data/test_data.json`、晋升 Skill
- **SQLite 统一库**：sessions、messages、artifacts、selector_registry、rag_chunks、skill_candidates。
- **注意**：UI 变更 stale 降权、脏数据不进正式库、CI 默认不依赖 LLM 执行路径。

## 对话 4：四层工程级记忆 + 微内核 + 幻觉控制

### 用户问题
工程级记忆至少 4 层？微内核好扩展？不懂定位的人能否 Chat 自动定位写用例？幻觉度高吗？

### 结论摘要
- **四层记忆**：
  | 层 | 名称 | 存储 |
  |----|------|------|
  | L1 | 工作记忆 Working | 当前会话 context |
  | L2 | 情景记忆 Episodic | 完整 session 轨迹 |
  | L3 | 语义记忆 Semantic | selector_registry + RAG |
  | L4 | 程序记忆 Procedural | skills/ |
- **微内核**：内核 Engine + DataDriver + execute_test_case 不变；AI/记忆/Chat 为扩展层 → 质的飞跃。
- **不懂定位的人**：自然语言 → DOM grounding（必须从 tool 返回的真实 DOM 选 selector）→ 标准 JSON → 试跑 → 确认保存。
- **幻觉控制**：
  - 高风险：无 DOM 猜 selector、不试跑就保存
  - 低风险：Tool grounding + 立即 execute + schema 校验 + 记忆降权
  - 产品表述：「AI 辅助生成并试跑，通过后确认保存」

## 设计原则（贯穿全部对话）

1. **默认关闭**：`llm.enabled: false`，无 API Key 零影响
2. **确定性 CI**：`main.py` 路径不被 Agent 污染
3. **Grounding 优先**：selector 必须来自 DOM，不能纯 LLM 编造
4. **确认落盘**：写 `data/` 和晋升 Skill 需确认或阈值
5. **微内核扩展**：新能力全部在 `ai/` 扩展层，不动 core 逻辑
